The mark is a bow tie: two folded wings meeting at a square knot, with two
buttons below — the butler's collar over the shirt studs. It has two framings,
and they are different objects rather than one drawing with and without a tile.

**In chrome** — the rail, the header, the account bar — it is the **bare
glyph**: a neutral ink, level, on whatever surface it is handed — near-black on
light, cream on dark. This is the one framing sitting on a ground it does not
own, so it is the one thing keyed on light or dark mode.

**On display surfaces** — the browser tab, the launcher, the social card, the
README lockup — it wears the **chip**: a flat burnt-orange tile with the bow cut
out of it in cream, level, and inset so the tile keeps ground around it. The
chip is a single colourway in both modes. It is a saturated object, not a
surface; it isn't borrowing the page's tone, so it has no reason to follow the
page's mode.

## The knot is back

The mark was two shapes for a year: [ADR-0053](/docs/architecture) deleted the
knot because its only job was to be a _different colour_ from the cloth it lay
on, and at favicon size that boundary was four pixels wide and measured
**1.40:1** — while every contrast test passed, because they all held ink against
_ground_ and none held ink against ink.

[ADR-0055](/docs/architecture) brings it back, because what changed is not the
knot but the mark's colour. The bow is a **single ink** in every framing now, so
the knot and the buttons carry the wings' own fill. The gaps between them are
_ground_ showing through, not an ink-against-ink edge — so the only contrast
boundary the mark has is still itself against its surface, exactly as ADR-0053
required. A same-ink knot costs nothing the coloured one could not afford.

### What is measured, and where it is worst

The bare glyph is a single ink, so it has exactly one boundary: itself against
the surface it was handed. Each colourway is measured only against the surfaces
it can actually land on — page and card, of every theme in its mode. Neutral
ink clears its ground with enormous room, which is the point of moving the
colour off the bow:

|                         | worst       | on                     |
| ----------------------- | ----------- | ---------------------- |
| glyph on light surfaces | **11.71:1** | tokyo-night-light page |
| glyph on dark surfaces  | **12.99:1** | gruvbox-dark page      |

The chip takes no mode, so its **flat** tile faces all 14 themes at once. There
is no gradient stop to fail on one ground and clear on another — the single
ember carries the edge, and it clears the graphics floor on every surface it
lands on:

|           | worst  | on                     |
| --------- | ------ | ---------------------- |
| chip tile | 3.19:1 | tokyo-night-light page |

The chip's own interior edge, and its habitat — the surfaces it lands on that
are not Steward's:

|                       | ratio  |
| --------------------- | ------ |
| bow against the tile  | 4.01:1 |
| tile on Chrome, light | 3.47:1 |
| tile on Chrome, dark  | 3.54:1 |
| tile on GitHub, light | 4.55:1 |
| tile on GitHub, dark  | 4.16:1 |

### How the chip places it

The bow is 54 × 22 units at an aspect of 2.45:1 — 84% of the tile's width.
Every chip insets the **whole mark** — bow, knot and buttons — through one
function; the chip keeps a hair of ground, and the maskable fills more of its
safe zone so the full-bleed square reads bold:

|               | scale              | bow spans | of the visible tile | ground per side |
| ------------- | ------------------ | --------- | ------------------- | --------------- |
| chip          | `CHIP_INSET` 0.92  | 49.7u     | 78%                 | 7.2u            |
| maskable icon | `MASK_INSET` 0.853 | 46.1u     | 90%                 | 2.6u            |

The maskable column measures against the safe zone — the middle 80% a launcher
is guaranteed to show. Its bow fills 90% of that zone, bolder than the chip's
share of its tile so the full-bleed square does not read small, and kept off the
mask so a launcher's crop never reaches the tips.

The bow is **level in every framing** (`CHIP_TILT` 0°): it is symmetric by
construction and the tile is square, so a rotation fights both.

## Why the chip is flat

The chip carries no border and no gradient. The border went first: it existed
only because the old tile sat within a hair of the page tone, and at 16px a
one-unit stroke on a 64-unit tile is a quarter of a device pixel — a feature
that never rendered on the surface it existed for.

The gradient went with the rebrand (ADR-0055). The old two-stop tile ran a
diagonal so that at least one stop cleared each ground; the flat `#c75117`
clears the graphics floor on every surface the chip lands on by itself — ≥3.19
across the fourteen themes, ≥3.47 on the browser tab strips — so there is
nothing for a gradient to buy. A flat object is one drawing at every size, and
the `.ico` could never carry a gradient faithfully anyway. The table above
asserts the edge rather than assuming it.

## Two gates, and why neither is enough

`theme.test.ts` holds **every visible boundary** at 3:1 — not every ink against
its background, which is a different set and is the set that let a 1.40:1 edge
ship. `mark.test.ts` holds **every drawn feature at one device pixel** at the
declared minimum, because contrast says two regions differ and never says
either is big enough to be a region.

Both can fail automatically. Neither can tell you whether the thing reads as a
bow tie, so `brand/proof/` holds renders at true device pixels, magnified with
nearest-neighbour — what you enlarge is the real raster, not a clean re-render
of the vector at a larger size. Regenerate them with `node scripts/mark-sheet.ts`.

The sheets cover Steward's fourteen themes and, separately, the surfaces the
chip actually lands on: Chrome's and GitHub's light and dark chrome. A favicon
tested only against its own app's themes has not been tested.
