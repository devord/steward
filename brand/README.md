# Brand kit

The mark is a **bow tie** — the butler's uniform, one shape. Everything in this
folder is generated from `apps/web/app/lib/mark.ts` by
`node scripts/gen-brand.ts` (SVG) and `zsh scripts/render-icons.sh` (PNG).
**Nothing here is hand-edited**; CI re-runs both and fails if the tree moves.
Fix the geometry at the source and regenerate.

## Which file do I want?

| You are…                                             | Use                     | Why                                                                                        |
| ---------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------ |
| putting the logo in app chrome, a nav bar, a sidebar | `mark/`                 | The bare glyph. A tile in chrome either vanishes into the surface or punches a hole in it. |
| making a favicon, launcher, app-store or PWA icon    | `icon/`                 | The product-icon chip — it brings its own ground, so it holds an edge anywhere.            |
| heading a README, a docs page, a deck, a press item  | `wordmark/`             | Mark + name lockup.                                                                        |
| printing, embroidering, engraving, or given one ink  | `*-black` / `*-white`   | Solid one-colour cuts.                                                                     |
| unsure whether the viewer is in light or dark mode   | `mark/*-auto`           | One file, swaps itself via `prefers-color-scheme`.                                         |
| theming around the mark in code                      | `palette/identity.json` | The identity hexes, machine-readable.                                                      |

For the **glyph**, pick `-light` or `-dark` by the background it goes on, not
by the ink. The **chip has no variants**: it is one colourway in both modes
(ADR-0053), because a saturated object has no reason to follow the viewer's
page.

```
brand/
├── mark/        steward-mark-{light,dark,auto,black,white}.svg  + png/
├── icon/        steward-icon.svg, steward-icon-maskable.svg     + png/
├── wordmark/    steward-wordmark-{light,dark,black,white}.svg   + png/
├── palette/     identity.json
└── proof/       what it renders as, at true device pixels
```

SVG is the master in every case; the PNGs are convenience copies on
transparent backgrounds, at the sizes people actually paste into things.

## Rules

**Clear space** — keep **10 units of the mark's own 64-unit tile** free on all
four sides, roughly one sixth of the chip's width. Nothing sits closer than
that, including the edge of its own container. (This used to be stated as "one
knot width". There is no knot.)

**Minimum size** — the chip is validated to **16 device pixels** and the bare
glyph to **20 device pixels wide**. Device pixels at 1×, not CSS pixels on a
Retina display: the `.ico` frames are packed at 16, and Windows at 100% renders
there. Every drawn ratio clears one device pixel at those sizes, and
`mark.test.ts` fails if one stops doing so.

**The mark does not follow the theme.** Steward ships fourteen themes; the
identity is not one of them. The bare glyph has two colourways keyed on light
or dark mode alone; the chip has one, full stop.

**The chip owns its ground; the glyph does not.** On the chip the identity is
the tile and the bow is cut out of it. On any foreign surface the mark is the
bare glyph, flat, with no tile behind it — a tile in chrome either vanishes
into the sidebar or punches a hole in it.

### Don't

- Don't recolour it to match a page, a theme, or a client's palette.
- Don't add effects — no shadow, glow, outline, bevel, or extra rotation. The
  chip's 12° is part of the mark; a second rotation is not.
- Don't put a border on the chip. It doesn't need one, and at 16px a hairline
  is a quarter of a pixel.
- Don't stretch, condense, or re-space the lockup. Scale it as a whole.
- Don't rebuild the lockup by setting "Steward" next to the mark yourself —
  the spacing and the baseline are measured. Use `wordmark/`.
- Don't put the bare glyph on a busy photograph. Use the chip.

### What is measured, and where it is worst

The bare glyph is one shape, so it has exactly one boundary: itself against the
surface it was handed. Each colourway is measured only against the surfaces it
can actually land on — page and card, of every theme in its mode:

|                         | worst      | on                     |
| ----------------------- | ---------- | ---------------------- |
| glyph on light surfaces | **4.30:1** | tokyo-night-light page |
| glyph on dark surfaces  | **5.84:1** | gruvbox-dark page      |

The chip takes no mode, so its tile faces all 14 themes. It carries no border,
and **neither gradient stop holds an edge alone** — they fail on opposite
grounds, which is exactly why the gradient runs diagonally and puts both stops
on the perimeter. What is held is that at least one clears:

|                       | worst  | on                     |
| --------------------- | ------ | ---------------------- |
| tile, top of the fold | 2.72:1 | tokyo-night-light page |
| tile, deep end        | 2.41:1 | gruvbox-dark page      |

The chip's own interior edge, and its habitat — the surfaces it lands on that
are not Steward's:

|                                 | ratio  |
| ------------------------------- | ------ |
| bow against the tile's top      | 3.41:1 |
| bow against the tile's deep end | 5.40:1 |
| tile on Chrome, light           | 4.67:1 |
| tile on Chrome, dark            | 4.16:1 |
| tile on GitHub, light           | 6.12:1 |
| tile on GitHub, dark            | 4.89:1 |

## What it survives

`brand/proof/` holds the renders, at true device pixels and magnified with
nearest-neighbour so what you enlarge is the real raster. They are regenerated
by `node scripts/mark-sheet.ts`, and they are the thing to look at before
believing the numbers above mean the mark is legible — the two say different
things, and the mark once shipped at 1.40:1 with every number green (ADR-0053).

- Both framings at 16 / 20 / 24 / 32 / 64 device pixels, light and dark.
- Every theme Steward ships, page and card tiers.
- **The chip where it actually lands** — Chrome's and GitHub's light and dark
  chrome, which are not Steward's surfaces and are where a favicon lives.
- One ink, positive and reversed.

See `DESIGN.md § Mark` for the construction and ADR-0053 for why the bow is one
shape.
